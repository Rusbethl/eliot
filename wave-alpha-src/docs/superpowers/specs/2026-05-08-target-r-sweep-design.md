# `target_R` sweep — design

## 1. Motivation

The 2026-05-06 ablation grid Phase 2 included `target_source` as a
sweep axis, but the axis was degenerate — `_target_price` ignored
`rules.target_source` entirely (G7). Every cell produced bit-identical
fib-extension targets, so Phase 2's verdict could not actually rank
`fib_extension` against `fixed_R`.

The 2026-05-08 G7 wiring fix (v0.5.9, commit `4a900b6`) ships the
dispatch: `target_source="fixed_R"` now actually computes
`target_R × planned_risk` from the entry anchor on the profit side.
This unblocks a proper comparison.

This spec ships a small, single-axis grid sweep that ranks four
`target_R` values against the `fib_extension` baseline. The verdict
informs whether `fixed_R` ships as a new default in v0.6.0, stays
opt-in (MARGINAL), or remains documented but discouraged (NO-GO).

The scope is deliberately narrow: one axis, five cells, no other rule
permutations. The Phase 2 verdict already settled the other axes
(direction_modes, entry_trigger, stop_source, min_confidence) and
shipped the winners as v0.5.9 defaults; replaying them would only
add noise.

## 2. Goals and non-goals

**Goals**

- Produce a 5-cell grid result that ranks `fixed_R ∈ {1.5, 2.0, 2.5, 3.0}`
  against `fib_extension` on the curated 50-ticker universe,
  2020-2024.
- Apply a 0.05R three-tier GO / MARGINAL / NO-GO verdict (matches
  Phase 2 sensitivity threshold and EBT-validation convention).
- Render the grid markdown via existing `grid_report.render_grid_markdown`
  and a sibling verdict file describing the decision.
- Validate the G7 wiring under production conditions — i.e. catch
  any silent regression in `_target_price_fixed_r` that the unit
  tests would not surface.

**Non-goals**

- Sweeping additional axes (`min_confidence`, `direction_modes`,
  `entry_trigger`, `stop_source`). Phase 2 settled those; replaying
  them is out of scope.
- Sweeping `target_R` values outside `{1.5, 2.0, 2.5, 3.0}`. Edge
  values (R=1.0, R=4.0, R=5.0) are deferred to a follow-up sweep
  iff the curve shape is interesting in this run.
- Relaxing `max_holding_bars` for high-R cells. The empirical
  degree-2 EBT (17 expected, 29 max) is the user-facing reality;
  the verdict measures `fixed_R` *given the current time-stop*,
  not "would `fixed_R` win with infinite time?" That is a separate
  question (§9 W1).
- Re-running on a different universe or longer time window. The
  curated 50-ticker universe + 2020-2024 is the project's standard
  comparable harness; deviating breaks comparability with Phase 1/2.
- Multi-degree enumeration (S6) — degrees other than 2 are out of
  scope here; the empirical EBT for degree 2 is the only fit
  available, and `target_R` outcomes for other degrees would be
  dominated by the heuristic max_holding fallback (§9 W2).

## 3. Architecture

### 3.1 Run configuration — two YAMLs

The grid harness (`backtest/grid.py:GridConfig`) takes the Cartesian
product of axis levels — there is no explicit-cell-list mode. A naive
single-yaml with `target_source × target_R` axes would produce 8 cells
where 4 are duplicates (`fib_extension × target_R=*` ignores
`target_R`), wasting ~60% of runtime on redundant baseline runs.

The clean shape is two separate yamls + two CLI invocations, combined
in the verdict file:

**`configs/grid_target_r_baseline.yaml`** (1 cell, baseline):

```yaml
# target_R sweep baseline — fib_extension on the v0.5.9 default
# rules. Produces a single cell to compare against the 4-cell
# fixed_R sweep.  Spec: 2026-05-08-target-r-sweep-design.md.
axes:
  - name: target_source
    levels: [fib_extension]

fixed:
  direction_modes: [long]
  entry_trigger: immediate
  stop_source: atr_multiple
  min_confidence: 0.45
  time_stop_mode: degree_based
  slippage_bps: 5
```

**`configs/grid_target_r_sweep.yaml`** (4 cells, fixed_R sweep):

```yaml
# target_R sweep — 4 fixed_R cells across {1.5, 2.0, 2.5, 3.0}.
# Baseline runs from configs/grid_target_r_baseline.yaml.
# Spec: 2026-05-08-target-r-sweep-design.md.
axes:
  - name: target_R
    levels: [1.5, 2.0, 2.5, 3.0]

fixed:
  target_source: fixed_R
  direction_modes: [long]
  entry_trigger: immediate
  stop_source: atr_multiple
  min_confidence: 0.45
  time_stop_mode: degree_based
  slippage_bps: 5
```

The `slippage_bps: 5` matches Phase 2's `fixed` block to keep the
comparison apples-to-apples (Phase 2 verdict shipped at 5 bps).

Cell IDs (auto-generated by `GridCell.cell_id`):
- baseline: `target-fib-extension` (1 cell)
- sweep: `target_R-1.5`, `target_R-2.0`, `target_R-2.5`, `target_R-3.0` (4 cells)

Total: 5 distinct cells across two runs.

### 3.2 Harness reuse

`backtest/grid.py:run_grid(grid_config, *, base_cfg, provider)` is
called as in Phase 1/2. The harness already supports mixed-`target_R`
cells — the v0.5.9 dispatch is what was missing, and is now in place.
No grid harness change.

`grid_report.render_grid_markdown(result, *, config, phase_name="target_r")`
renders the output. The phase name "target_r" is a label; no schema
change.

### 3.3 Verdict file

After the grid run completes, hand-author a verdict file at
`reports/target-r-2026-05-08/verdict.md` summarizing:

- The 5-cell expectancy table (copied from grid.md for self-containment).
- The winner cell vs. baseline delta.
- Tier (GO / MARGINAL / NO-GO) per the §4 thresholds.
- Curve-shape commentary (monotonic? peak? flat?).
- Recommendation for v0.6.0 default and any follow-up sweeps.

This is *not* generated by the harness — it's analyst commentary on
the harness output, written after reviewing `grid.md`. The pattern
matches the Phase 1/2 verdict files
(`reports/grid-2026-05-06/phase1-verdict.md`).

## 4. Verdict criteria

Let `T0` = `fib_extension` baseline expectancy in R-multiples,
`Tbest = max(T1..T4)` over expectancy, and
`Δ = Tbest - T0`.

| Verdict | Threshold | Action |
|---|---|---|
| **GO** | `Δ ≥ +0.05R` | Ship `target_source="fixed_R"` with winning `target_R` as v0.6.0 default. Update `TradeRules.target_source` default and add `target_R` default. Update test fixtures. |
| **MARGINAL** | `Δ ∈ (-0.05R, +0.05R)` | Keep `fib_extension` default. Document `fixed_R` as an opt-in option in CLAUDE.md and the trade-rules docstring. No code change. |
| **NO-GO** | `Δ ≤ -0.05R` | Keep `fib_extension` default. Flag `fixed_R` in the docs as "implemented for completeness; not recommended on the curated universe — see target_R sweep verdict." Optionally add a comment near `_target_price_fixed_r`. |

The 0.05R threshold matches:
- Phase 2 axis-sensitivity threshold (§6.4 grid spec).
- The 2026-05-07 EBT validation `|delta|=0.0535R` MARGINAL boundary
  (the EBT spec shipped on the borderline).
- Project-wide convention for "meaningfully different" trade-sim
  expectancies.

Tie-breaker for `Tbest` when two cells are within `0.01R`: prefer
the lower `target_R` value (smaller targets hit more often, smoother
equity curve, less hit-rate variance). Document the tie in the
verdict file.

## 5. File structure

**New:**

- `configs/grid_target_r_baseline.yaml` — 1-cell baseline (§3.1).
- `configs/grid_target_r_sweep.yaml` — 4-cell fixed_R sweep (§3.1).
- `reports/target-r-2026-05-08/baseline.md` — baseline harness output
  (gitignored per `.gitignore` `reports/` rule).
- `reports/target-r-2026-05-08/sweep.md` — sweep harness output
  (gitignored).
- `reports/target-r-2026-05-08/verdict.md` — analyst commentary
  combining the two reports (gitignored).

**Not modified (harness reuse):**

- `src/wave_alpha/backtest/grid.py` — handles all cells in v0.5.9.
- `src/wave_alpha/backtest/grid_report.py` — handles arbitrary phase
  names.
- `src/wave_alpha/trades/derive.py` — G7 dispatch already wires
  `fixed_R`; no further change.

**Conditionally modified (only on GO verdict):**

- `src/wave_alpha/trades/models.py` — `TradeRules.target_source`
  default flips from `"count_target"` to `"fixed_R"`; `target_R`
  default flips from `None` to the winning value.
- `tests/trades/test_models.py:test_trade_rules_defaults` — update
  the assertions and the docstring referencing the verdict.
- `tests/trades/test_derive.py` — audit any test that relied on the
  default `target_source` and update if needed.
- `docs/superpowers/specs/2026-05-08-target-r-sweep-design.md` — fill
  §6 verdict.
- `pyproject.toml` + `__init__.py` — version bump to 0.6.0.

## 6. Verdict — MARGINAL (2026-05-08)

Run config: `data/universe_curated.txt` × 2020-01-01..2024-12-31.
Wall time: baseline 1h 25min, sweep 5h 51min.

| Cell                  | n    | hit  | avg R | expectancy | PF   |
|-----------------------|-----:|-----:|------:|-----------:|-----:|
| target-fib-extension  | 2242 | 0.42 | +0.22 | **+0.215** | 1.37 |
| target_R-1.5          | 3181 | 0.48 | +0.10 | +0.097     | 1.18 |
| target_R-2.0          | 2675 | 0.45 | +0.16 | +0.157     | 1.28 |
| target_R-2.5          | 2480 | 0.43 | +0.19 | +0.194     | 1.34 |
| target_R-3.0          | 2331 | 0.42 | +0.20 | +0.202     | 1.35 |

- **Best fixed_R cell:** `target_R-3.0` (+0.202R)
- **Baseline:** `target-fib-extension` (+0.215R)
- **Δ = −0.013R** → MARGINAL per §4 thresholds.

The four fixed_R cells produce a monotonically increasing expectancy
curve approaching `fib_extension` from below: the gain from R=2.5 to
R=3.0 is +0.008R, nine times smaller than the gain from R=1.5 to R=2.0
(+0.060R). `fib_extension` appears to be a soft upper bound under the
current rules and time-stop configuration. All cells have n ≥ 2,331
trades — sample sizes are not the limiter.

**Action (per §10 MARGINAL):** keep `fib_extension` as the v0.5.9
default. No code change. `fixed_R` remains an opt-in. The companion
verdict file at `reports/target-r-2026-05-08/verdict.md` (gitignored)
contains the full curve commentary and recommends W1 (relax
`max_holding_bars` for high-R cells) as the natural follow-up — the
curve is still rising at R=3.0, suggesting time-stop interference may
be capping the high-R cells.

## 7. Lookahead and other invariants

- `PointInTimeView` is unchanged. No new fetch sites; the harness
  uses the same `CachedProvider` as Phase 2.
- LLM mode is `disabled` for comparability with Phase 1/2 baselines.
- The synthetic-leak test (`tests/backtest/test_lookahead_guard.py`)
  remains green — this spec adds no new code paths.
- The G7 dispatch is unit-tested at the per-candidate boundary
  (`tests/trades/test_derive.py:test_target_source_fixed_R_*`); the
  grid sweep is the integration-level confirmation that those units
  produce the expected user-facing behavior across the universe.

## 8. Risks and mitigations

| Risk | Mitigation |
|---|---|
| `fixed_R` time-stops more often than `fib_extension` because targets are placed further out at high R, reducing hit rate disproportionately | Acknowledged — this is the *user-facing reality* the verdict measures. If MARGINAL, a follow-up spec relaxing `max_holding_bars` for high-R cells can answer "is fixed_R inherently better with more time?" |
| Cache pre-warming inconsistency between cells (some hit cache, some hit yfinance) | All cells use the same universe + date range. Run baseline yaml first (§12) so the cache is fully warm before the sweep yaml runs. |
| The grid harness produces a `GridResultRow` per cell; the report renderer assumes consistent column shape | Each yaml's axis names are scalar (`target_source` for baseline, `target_R` for sweep); `_short_axis_value` handles both. Verified visually after the baseline run before launching the sweep. |
| `target_R=3.0` produces signals with rr=6.0 and very low hit rates that could blow up sample variance for that cell | ~400 trades/cell at the curated-universe scale (Phase 2 historical). Even at R=3 with 20% hit rate, ~80 winners is enough for a stable expectancy estimate. If post-run sample shows <100 trades/cell, treat as low-confidence and fold into MARGINAL. |
| Re-running fits LLM cache that's now stale (LLM disabled, but other caches) | LLM mode is `disabled` and never opens its cache. The OHLCV cache auto-refreshes per the `CachedProvider` policy. No staleness risk. |

## 9. Open issues / deferred decisions

| # | Question | Defer to | Reason |
|---|---|---|---|
| W1 | Should `max_holding_bars` be relaxed for high-R cells to test `fixed_R`'s inherent fitness without time-stop interference? | Future follow-up iff this sweep is MARGINAL | Verdict measures user-facing reality first. If MARGINAL, the question becomes "would `fixed_R` win with more time?" — that's a separate experimental design. |
| W2 | Should `target_R` be re-validated per-degree once multi-degree enumeration (S6) ships? | Future follow-up post-S6 | The current empirical EBT covers degree 2 only; per-degree `target_R` interaction is uninvestigated. |
| W3 | Should we sweep the heroic edges (`target_R=4.0`, `5.0`) to find the right tail of the curve? | Future follow-up iff coarse sweep shows monotonic increase to R=3 | Coarse sweep first; if R=3 is the peak, no point chasing further; if R=3 is still increasing, extend. |
| W4 | Should this also sweep `entry_trigger=confirmation` to test whether confirmation entries change the optimal R? | Out of scope | Phase 1 verdict shipped `entry_trigger=immediate` and replaying it is wasted compute on a single-axis sweep. |
| W5 | Should `fixed_R` cells use a different `min_confidence` than the v0.5.9 0.45 default? | Out of scope | Single-axis discipline. Per-pattern `min_confidence` (G3) is its own follow-up. |

## 10. Roadmap impact

If **GO**: this is the v0.6.0 minor release — first user-facing
behavior change from a target-side sweep. Update `TradeRules`
defaults, ship verdict file, bump version. The change is
schema-compatible (default-flip only; existing configs that set
`target_source` explicitly are unaffected).

If **MARGINAL**: no code change. This spec ships the verdict file
only. v0.5.9 stays the head; `fixed_R` is documented as an opt-in.

If **NO-GO**: no code change. Verdict file documents the negative
result. `fixed_R` stays available but discouraged.

The next phase regardless of verdict is **S6 multi-degree
enumeration** (still deferred from the 2026-05-05 sanity run §9).
That work is not gated on this verdict.

## 11. Estimated runtime

~3-5h on the curated 50-ticker universe over 2020-2024:

- 5 cells × ~1,000 trades/cell ≈ 5,000 trades total (Phase 2 produced
  ~16,000 trades with 32 cells, so 5 cells ≈ 5,000 ballpark).
- Per-cell engine work dominated by ATR-stop computation + count
  enumeration; both are cached. First cell warms the cache, others
  reuse.
- LLM disabled — no API latency.
- Pre-warming script (`scripts/prewarm_4h_cache.py`) need not be
  run; the curated universe is already cached from Phase 2.

Run commands:

```bash
# Baseline (1 cell, ~30-50 min)
uv run wave-alpha backtest grid \
    --universe data/universe_curated.txt \
    --start 2020-01-01 --end 2024-12-31 \
    --grid configs/grid_target_r_baseline.yaml \
    --out reports/target-r-2026-05-08/baseline.md \
    --phase-name "target_R baseline"

# Sweep (4 cells, ~2-4h)
uv run wave-alpha backtest grid \
    --universe data/universe_curated.txt \
    --start 2020-01-01 --end 2024-12-31 \
    --grid configs/grid_target_r_sweep.yaml \
    --out reports/target-r-2026-05-08/sweep.md \
    --phase-name "target_R sweep"
```

CLI flags match the existing `wave-alpha backtest grid` interface
(verified against `--help` output 2026-05-08): `--universe`,
`--start`, `--end`, `--grid`, `--out`, and `--phase-name`. No CLI
extension required.

Verdict authoring: ~30 minutes after both grids complete.

## 12. Run discipline — start order

Run baseline **first**, sweep **second**. Two reasons:

1. The first run primes the OHLCV cache (`~/.wave_alpha/cache.sqlite`)
   for all 50 tickers across 2020-2024. The 4-cell sweep then reads
   from a fully-warm cache and exhibits stable per-cell timing.
2. If the baseline run surfaces any unexpected behavior (e.g., zero
   trades, empty bars), abort before consuming the larger sweep
   compute budget.

Total wall time: ~3-4.5h (baseline 30-50 min + sweep 2-4h).
